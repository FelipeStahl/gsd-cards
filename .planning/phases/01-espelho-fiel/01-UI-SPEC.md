# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This is a Tauri v2 desktop app (React 19 + Tailwind 4 webview), not a responsive website. All measurements below target desktop window sizes (comfortable ≥1024px width) and native-feeling density. No mobile breakpoints. UI follows OS light/dark theme (`prefers-color-scheme`), not a manual toggle, in this phase.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, badge inner padding |
| sm | 8px | Compact element spacing (card internal stack) |
| md | 16px | Default element spacing (card padding, column gap) |
| lg | 24px | Section padding (header padding, panel padding) |
| xl | 32px | Layout gaps (column-to-column outer margin, panel section breaks) |
| 2xl | 48px | Major section breaks (board top margin under header) |
| 3xl | 64px | Page-level spacing (empty-state vertical centering) |

Exceptions:
- Minimum interactive hit area for icon-only buttons: **32×32px** (not the 44px touch target default — this is a desktop mouse-driven app, not touch)
- Status dot indicators (sync health, card status): **8px** fixed diameter, exempt from the scale since they are decorative, not spaced elements

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 12px | 600 (semibold) | 1.4 |
| Body | 14px | 400 (regular) | 1.5 |
| Heading | 18px | 600 (semibold) | 1.3 |
| Display | 24px | 600 (semibold) | 1.2 |

Only 2 weights used app-wide: 400 (regular) and 600 (semibold). Never use 500 or 700 — pick the nearest of these two.

Usage mapping:
- **Label** (12px/600): status badges, column headers, requirement/plan counters, sync indicator text, "inserida" badge
- **Body** (14px/400): card description text, panel tree rows, modal-rendered markdown body text, empty/error state body copy
- **Heading** (18px/600): card title (phase name), detail panel section titles, modal artifact filename header
- **Display** (24px/600): app header project name, empty-state heading

## Color

App follows OS theme. Both light and dark values declared; implement via CSS variables swapped on `prefers-color-scheme` (or a `data-theme` attribute if Tauri needs manual detection).

| Role | Light | Dark | Usage |
|------|-------|------|-------|
| Dominant (60%) | `#ffffff` | `#0b0d10` | App background, board canvas background |
| Secondary (30%) | `#f4f4f5` (zinc-100) | `#18191c` | Sidebar, header bar, drawer rail, card surface, column background |
| Accent (10%) | `#6366f1` (indigo-500) | `#818cf8` (indigo-400) | Primary CTA buttons, active/selected card border, progress bar fill, focus rings, update-highlight glow |
| Warning | `#f59e0b` (amber-500) | `#fbbf24` (amber-400) | Parse-failure badge/dot, blocked badge, stale-sync indicator, "Preparando"/"Em execução" status dots |
| Success | `#10b981` (emerald-500) | `#34d399` (emerald-400) | "Concluída"/verified status dot, healthy sync indicator text, requirement-covered checkmark |
| Destructive | `#ef4444` (red-500) | `#f87171` (red-400) | **Reserved, not used this phase** — board is read-only (no delete/archive actions exist until Phase 2/4). Token declared now for consistency across phases. |

Accent (indigo) reserved for: primary CTA button ("Abrir projeto"), the active-card outline/glow on real-time update (D-13), plan-progress bar fill, focus outline on keyboard navigation, links inside the artifact modal (e.g. "Ver artefato"). Never used for large fills or as a default text color — text stays neutral gray/zinc.

Status colors are applied narrowly (small dot + badge text only, never full-card fills) so the 60/30/10 dominant/secondary/accent ratio holds across the overall board surface — see Status Badge Mapping below.

├───────────────┬─────────────────────────────────────┬───────────┤
│ Sidebar        │ Board (scrollable, horizontal cols) │ Drawer    │
│ 240px fixed    │ flex-1, min-width 1024px comfortable│ rail 48px │
│ secondary bg   │ dominant bg, 32px outer padding      │ secondary │
│                │                                       │ bg        │
│ Placeholder:   │ 4 columns, 16px gap, 280px min-width │ Placeholder:│
│ "Sessões       │ each, sticky column header (Label    │ terminal  │
│ (em breve)"    │ style + count)                        │ icon,     │
│ — Phase 2      │                                        │ disabled, │
│                │ Below columns: collapsed history strip│ tooltip   │

- Sidebar: 240px fixed width, not collapsible in Phase 1. Content: single placeholder row, muted body text, no interaction.
- Drawer: collapsed by default this phase — a slim 48px icon rail, not a full 400px panel. One disabled terminal icon (lucide `TerminalSquare`) with tooltip pointing to Phase 2. Expanding is out of scope until Phase 2 builds the real terminal.
- Header: spans full width above sidebar+board+drawer (acts as the app's persistent status bar, not scoped to just the board column area).
- Board: below min comfortable width (1024px), columns do NOT shrink below 280px — the board scrolls horizontally instead of compressing card content.

## Board Column Mapping (D-05, D-06)

4 grouped columns, left to right. Every card additionally always shows its exact gsd-core status as a badge (D-06) — grouping never hides the real state.

| Column (Label, pt-BR) | i18n key | gsd-core statuses included |
|---|---|---|
| A fazer | `board.column.todo` | `pending` |
| Preparando | `board.column.preparing` | `discussed`, `planned` |
| Em execução | `board.column.executing` | `executing`, `executed` |
| Concluída | `board.column.done` | `verified` |

"Executed without verified" stays in **Em execução** with a warning-colored badge — never promoted to Concluída (D-05, product stance: verification is what completes a phase, not execution alone).

Column header anatomy: Label-style text (12px/600) + count badge (e.g. "3"), sticky to top of scroll area within the column.

Ordering within a column: numeric phase order (1, 2, 2.1, 2.2, 3...). Decimal/inserted phases (D-07) render as a normal card in numeric position with a small neutral "inserida" badge — no urgency styling (no color, no border treatment beyond the badge itself).

Badge = neutral secondary-surface pill (Label typography) + small 8px colored dot. Never a full-color fill — keeps the board's dominant/secondary color budget intact even with 6+ distinct statuses.

| gsd-core status | Dot color | Badge text (pt-BR) |
|---|---|---|
| `pending` | zinc-400 (neutral) | "pendente" |
| `discussed` | indigo-400 (accent) | "discutida" |
| `planned` | indigo-400 (accent) | "planejada" |
| `executing` | amber-500 (warning) | "em execução" |
| `executed` | amber-500 (warning) | "executada" |
| `verified` | emerald-500 (success) | "verificada" |
| unparseable / unknown | amber-500 (warning), with `AlertTriangle` icon instead of dot | "não reconhecida" |

## Card Anatomy (D-09)

Dense closed card. Padding 16px (md), corner radius 8px, secondary surface, min-height ~92px.

Top to bottom / left to right:
1. Row 1: phase number + name (Heading 18px/600, truncate with ellipsis) — "inserida" badge inline if decimal phase (D-07)
2. Row 2: exact status badge (see mapping above) + blocked badge if `STATE.md` reports a blocker for this phase (warning `AlertTriangle` icon + "bloqueada" label, Label style)
3. Row 3: plan progress bar — 4px height track (secondary-darker), accent-indigo fill, with "2/3" Label-style text right-aligned next to it
4. Row 4: requirement count — small `ListChecks` icon + "3 requisitos" (Label style, muted)

Click target: entire card is clickable, opens the detail panel (D-10). Hover state: 1px accent-colored border appears (no shadow elevation change — keep it flat/native-feeling).

Real-time update highlight (D-13): when a card's underlying data changes, apply a ~1000ms glow — `box-shadow: 0 0 0 3px {accent at 30% opacity}` easing `ease-out`, fading to none. No layout shift, no toast.

## Detail Panel (D-10)

Triggered by clicking a card. Right-side overlay panel, 480px wide, slides in over the drawer rail (not inline in the column — board stays visually stable).

- Header: breadcrumb "Fase N: Nome" (Heading style), close button (top-right, `X` icon, 32×32 hit area)
- Body: tree — Fase → Planos → Tarefas, each artifact row (PLAN/SUMMARY/VERIFICATION) shows filename (Body style, monospace for the filename token) + "Ver artefato" link button (accent-colored text, opens the modal — D-11)
- Unparseable artifact row: same row treatment but with the warning dot + "não reconhecida" and the "Ver artefato" link opens the modal directly in raw mode (BOARD-05)
- Footer: none

---

## Artifact Modal (D-11)

"GitHub preview" style — large centered modal over the board (not inside the detail panel).

- Max-width 900px, max-height 85vh, centered, dominant-surface background, backdrop dims the board (secondary-surface at 60% opacity, click-outside or `Esc` closes)
- Header: filename (Heading 18px/600, monospace), close button (32×32 `X`)
- Body: scrollable. Rendered mode: GFM markdown via `react-markdown` + `remark-gfm` (tables, `- [ ]` checklists render as real checkboxes, disabled/read-only). Raw mode (parse failure): amber warning banner at top ("Falha ao processar — exibindo conteúdo bruto. Motivo: {{reason}}") + monospace raw text body, no markdown rendering attempted
- No footer actions — this is read-only, closing is the only action

## Real-Time & Degradation States (D-13, D-14, D-15, D-16)

| State | Visual treatment |
|---|---|
| Healthy sync | Header sync indicator: 8px emerald dot + "Sincronizado há {{seconds}}s" (Label style, muted text) |
| Card updated (debounced) | 1000ms accent glow on the affected card only (see Card Anatomy) — no toast, no page-level indicator |
| Localized parse failure (BOARD-05) | Only the affected card shows the warning badge; rest of the board renders normally. Artifact opens in raw mode from the detail panel, never blocks the whole board |
| Watcher degraded/dead (D-16) | Board freezes at last-known-good state. Header sync indicator flips to amber dot + "Desatualizado desde {{HH:MM}}" + inline "Reconectar" button (accent text button). Auto-retry happens silently in the background; indicator only updates when reconnect actually succeeds |
| `.planning/` missing at open time (PROJ-02) | Full-page empty/error state (see Copywriting Contract), not a board with zero cards — the app never pretends a non-GSD folder is a valid project |

Debounce window: 150–300ms starting point (per `PITFALLS.md` Pitfall 4), tune empirically against real `/gsd-execute-phase` write bursts. Not a hard visual contract value — implementation detail left to planner/executor, but the **visual result** (no flicker, single glow per settled batch, never an intermediate broken card) is the contract.
