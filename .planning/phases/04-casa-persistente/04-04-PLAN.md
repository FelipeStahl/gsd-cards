<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app-state.json recent root → openProject | Persisted path re-validated before any read |
| dialog-selected raw folder → spawn cwd | User-chosen path becomes a process working directory |
| STATE.md content of a recent → health render | Untrusted markdown parsed for the card |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-09 | Tampering | Recent root opened from a card | high | mitigate | ProjectCard/openProject re-run `validateProjectRoot` (canonicalize + `.planning/` containment) before any read; a tampered/moved path degrades to the error card, never a crash or escaped read |
| T-04-10 | Tampering | Raw folder path passed to createProjectSession as spawn cwd | medium | mitigate | Path comes only from the OS-native `open({directory:true})` dialog (never typed/constructed) and is passed as `CommandBuilder::cwd` spawn arg, never concatenated into a shell string (04-RESEARCH Security Domain) |
| T-04-11 | Information Disclosure | App writing into `.planning/` during create | medium | mitigate | The app never writes `.planning/`; `/gsd-new-project` (GSD) creates it via terminal injection — asserted by the no-app-write acceptance grep |
| T-04-12 | Information Disclosure / prompt injection | Malicious `.planning/`/`CLAUDE.md` in a recent folder | low | accept | Inherent to opening ANY untrusted folder as a GSD project (already true since PROJ-02); Claude Code's own trust-folder prompting is the external mitigation layer, out of scope to re-mitigate here |
</threat_model>
