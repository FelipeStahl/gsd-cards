<objective>
PROJ-05 (board/header half): let the user hold several projects open at once and move between them without any session dying. Add multi-project state to board-store — a set of `openProjectRoots` plus one `activeProjectRoot` — and a `switchProject(root)` action that adopts 04-RESEARCH.md's **single-watcher-resync** decision (Pattern 3): keep exactly ONE active `notify` watcher for the active project, and on switch stop it, re-run openProject's parse steps for the newly-active root, and start a fresh watcher — rather than rewriting `WatcherState` into a per-project `HashMap`. Add the Header's `ChevronLeft` Home control (per 04-UI-SPEC `## Project Switcher`) that returns to the home view; the home grid itself is the switcher for opening a *different* recent (no dropdown component — 04-CONTEXT "sem router novo").

Purpose: multi-project is the "casa persistente" backbone. Sessions already survive switches (they live in session-store's module-level `liveSessions` Map, which board-store's openProject/closeProject never touch), so the risk is accidentally regressing that — switching must NOT call the destructive `closeProject` and must not depend on it.

Named decision (do not "improve" mid-phase): single active watcher + full re-sync on switch. A backgrounded project does NOT live-reflect `.planning/` changes; it re-syncs fully on next switch. This is acceptable for v1 (core value = real-time for the *active* board) and is deliberately NOT a per-project watcher HashMap — that rewrite would also require changing watch.ts's `unlistenChanged` singletons and reprocessPaths's single-project assumption.
</objective>

## Phase Goal (user story)

**As a** GSD user with several projects on the go, **I want to** switch between open projects and return to the home screen, **so that** I can jump around my work without ever losing a running Claude session. *(Derived from ROADMAP Phase 4 Success Criterion #3.)*
