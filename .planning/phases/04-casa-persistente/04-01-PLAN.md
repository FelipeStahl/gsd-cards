<objective>
Tracer slice for Phase 4: prove the app's FIRST-EVER disk write end-to-end. Install the two official Tauri persistence/notification plugins behind a legitimacy gate, register them with least-privilege capabilities, then wire ONE path through every persistence layer — open a project → persist a recent to appDataDir/app-state.json → read it back on reload → render it on a minimal home view → click it to reopen.

Purpose: De-risk the write-capability foundation (per orchestrator directive) before recents-health, multi-project, restore, rename, and notifications are built on top. If plugin-store cannot write to appDataDir, or the granular capability set is wrong, or the view-state branch cannot render before the board shell, this tracer fails FAST on the agent's best early-context tokens instead of after ten committed layers.

Output: `src/persistence/app-store.ts` (metadata store wrapper), both plugins installed/registered/scoped, and a working home→persist→reload→render→reopen loop. This is production-quality skeleton, not a prototype — the minimal home render is a functionality gap that plan 04-04 fills into the full grid; the persistence architecture (split-file layout, granular perms, view-state branch, upsertRecent seam) is real and kept.

Invariant (from 04-CONTEXT.md Phase Boundary): every write here targets appDataDir via @tauri-apps/plugin-store — NEVER the user's `.planning/`. The board stays read-only over `.planning/`.
</objective>

## Phase Goal (user story)

**As a** GSD user, **I want to** have the app remember the projects I have opened, **so that** I can reopen a recent project on the home screen without hunting for its folder again. *(Derived from ROADMAP Phase 4 Success Criterion #1; this plan delivers the persistence + minimal render slice of it.)*

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| npm/crates registry → build | Third-party package bytes enter the supply chain (first new deps since Phase 1) |
| appDataDir/app-state.json → app | User-tamperable plaintext JSON read back at runtime (paths, names) |
| frontend → Tauri store plugin (IPC) | Write requests cross into the plugin's capability-scoped file I/O |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-SC | Tampering | npm/cargo installs (plugin-store, plugin-notification) | high | mitigate | Task 1 blocking-human legitimacy gate before install; both official tauri-apps org, same repo as three trusted plugins; crates OK on crates.io telemetry |
| T-04-01 | Tampering | app-state.json `recentProjects[].root` read back on click | high | mitigate | Every recent root is re-opened through the existing `validateProjectRoot` gate (canonicalize + `.planning/` containment) before use — a tampered path fails validation or grants only the same read-only scope the user could grant manually (no escalation) |
| T-04-02 | Elevation of Privilege | Over-broad store/notification capability grant | medium | mitigate | Task 2 grants only granular per-command `store:allow-*` / `notification:allow-*`, never the bundled catch-all set (codebase least-privilege discipline) |
| T-04-03 | Information Disclosure | Persisting anything into the user's `.planning/` | medium | mitigate | Store file is `app-state.json` under appDataDir only; product invariant enforced by design and documented in app-store.ts + capability description |
</threat_model>
