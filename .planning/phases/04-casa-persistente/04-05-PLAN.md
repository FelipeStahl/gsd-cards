<objective>
PROJ-05 (session half) + SESS-05. Two tightly-coupled sidebar concerns that both extend `SessionDescriptor` and `SessionRow`:

1. **Session scoping (PROJ-05 prerequisite / pre-existing bug fix):** `session-store.ts`'s `sessions[]` is a single flat array with no project association — invisible while only one project could be open, but the moment 04-03 lets a second project be open, the sidebar mixes both projects' sessions (04-CONTEXT: "hoje ela mistura sessões de projetos diferentes — bug a corrigir"). Add `projectRoot` to `SessionDescriptor`, populate it everywhere a descriptor is created/discovered, and filter the sidebar by `activeProjectRoot`. Add the `SidebarScopeBanner` so the now-correct filtering is legible ("Mostrando sessões de: {projectName}"), not a silent fix. `projectRoot` is also load-bearing for SESS-04 resume (04-06 reads the session's OWN projectRoot for `--resume` cwd), so this field serves two requirements.

2. **Rename (SESS-05):** add `name?` to `SessionDescriptor`, a transition-gated `renameSession(id, name)` action persisted via app-store, and an inline-edit affordance (`RenameSessionControl`, a `Pencil` hover button leftmost in SessionRow's action group) — Enter/Check confirms, Esc/X cancels, empty clears back to the derived `Sessão <id8>` label. No ConfirmDialog (rename is reversible/low-stakes).

Purpose: make the sidebar project-aware and its sessions renameable — closing the PROJ-05 leak and delivering SESS-05, while extending `SessionDescriptor` once for both (and for 04-06's resume).
</objective>

## Phase Goal (user story)

**As a** GSD user juggling several projects, **I want to** see only the active project's sessions and give them memorable names, **so that** the sidebar reflects where I am and I can tell my sessions apart. *(Derived from ROADMAP Phase 4 Success Criteria #3 and #5.)*
