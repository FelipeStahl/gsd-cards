# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This is the DELTA on top of `.planning/phases/01-espelho-fiel/01-UI-SPEC.md`. Phase 1's design system (spacing scale, typography scale, color tokens, desktop-only scope note, i18n-keys-from-day-one rule) is the standing contract and is **reused verbatim**, not redefined. This document only specifies what Phase 2 adds: the sessions sidebar, the tool-missing state (PROJ-04), the embedded terminal in the right drawer (TERM-01/02), the terminal search bar (TERM-03), multi-terminal focus states (SESS-03), and session lifecycle affordances (SESS-06). Generated in autonomous mode (`--auto`) — no user was interrupted with questions; every open design decision below was resolved with a documented default and logged in `## UI Considerations` as `backstop` or `unresolved` where genuine ambiguity remained.

**Autonomous-mode resolution note:** `/gsd-discuss-phase` was not run for this phase (no `CONTEXT.md` exists) and `02-RESEARCH.md` is a technical/architecture document, not a design-decision log. All copywriting, layout, and state-treatment decisions below are therefore this researcher's prescriptive defaults, informed by `02-RESEARCH.md`'s architecture patterns and Phase 1's established visual language — not user-confirmed choices. Treat every row in `## UI Considerations` marked `unresolved` as an explicit planner assumption to flag, not a locked decision.

## Spacing Scale

Unchanged — reuse the Phase 1 scale verbatim (`xs` 4px through `3xl` 64px, all multiples of 4). See `01-UI-SPEC.md` `## Spacing Scale` for the full table.

Exceptions this phase (additive to Phase 1's icon-only 32×32 exception):
- Session row hover action buttons (Archive, Delete): **32×32px** hit area — same icon-only exception as Phase 1, not a new rule.
- Terminal search bar height: **36px** (slightly taller than the 32px icon standard to comfortably fit an input field with visible focus ring) — a documented, deliberate exception, not a scale violation.
- Status dot on session rows: **8px** fixed diameter — same decorative exemption as Phase 1's status dots, reusing the existing `.status-dot` CSS classes and `statusDotVariants` CVA (no new dot component).

## Typography

Unchanged — reuse the Phase 1 4-role scale verbatim (Label 12px/600, Body 14px/400, Heading 18px/600, Display 24px/600, only weights 400/600 anywhere). See `01-UI-SPEC.md` `## Typography` for the full table and usage mapping.

**New usage mapping this phase:**
- **Label** (12px/600): session row timestamp, session group headers ("ATIVAS"/"HISTÓRICO", uppercase via CSS `text-transform`, not literal uppercase copy), search match-count text, tool-missing state's inline badge (if any)
- **Body** (14px/400): tool-missing state body copy, confirm-dialog body copy, empty-state body ("Crie uma sessão para conversar com o claude neste projeto.")
- **Heading** (18px/600): tool-missing state heading, confirm-dialog heading, terminal chrome session-name label
- **Display** (24px/600): not used by any new Phase 2 surface (sidebar/drawer are secondary surfaces, no page-level heading introduced)

**Terminal (xterm.js) type — technical parameter, not part of the 4-role UI-chrome scale:** the terminal's own cell rendering is a distinct technical setting the xterm.js `Terminal` constructor takes, not a UI-text role. Declared explicitly so the executor has an exact value instead of "pick something reasonable":

| xterm.js option | Value |
|---|---|
| `fontFamily` | `"JetBrains Mono Variable", ui-monospace, "Cascadia Code", monospace` (same mono stack as Phase 1's artifact code blocks) |
| `fontSize` | `13` (px) |
| `lineHeight` | `1.2` (xterm.js default cell-height multiplier; not the Phase 1 body/heading line-height tokens — this only affects terminal cell spacing) |
| `scrollback` | `5000` (lines — the explicit numeric answer to TERM-02's "scrollback com limite") |
| `cursorBlink` | `true` |
| `cursorStyle` | `"block"` |
| `copyOnSelect` | `true` — selecting text in the terminal copies it to the clipboard immediately (standard terminal-app convention; avoids relying on `Ctrl+C`, which the shell/claude process needs for SIGINT) |
| `disableStdin` | `false` while the session's PTY is alive; set to `true` once the session has exited (see `## Session Status States`) |

## Color

Unchanged tokens — reuse the Phase 1 palette verbatim (`--color-dominant`, `--color-secondary`, `--color-accent`, `--color-warning`, `--color-success`, `--color-destructive`, `--color-foreground`, both light/dark values). See `01-UI-SPEC.md` `## Color` for hex values.

**First phase this destructive token is actually used** (Phase 1 declared it "reserved, not used"): the Delete-session confirm action is the sole consumer this phase — see `## Session Lifecycle Affordances`.

**Session status dot mapping** (reuses the existing `statusDotVariants` CVA/4-tone system from `StatusBadge.tsx` — no new tones, no new component):

| Session state | Tone (existing `StatusTone`) | Visual |
|---|---|---|
| Live process, currently focused in the drawer | `success` | Filled 8px dot, solid |
| Live process, running in background (not the focused terminal) | `success` | Filled 8px dot, identical to focused — focus is communicated by the row's selection treatment (accent left border), not by a different dot, so the dot always means "process is alive" unambiguously |
| Starting (spawn requested, PTY not yet confirmed) | `accent` | 8px dot with a CSS pulse animation (`opacity` 100%→40%→100%, 1200ms loop) — reuses `--color-accent`, no new token |
| Exited (process ended, normally or crashed) | `warning` | Filled 8px dot, static (no pulse) |
| Historical (`.jsonl` discovered on disk, no live `PtySession` backing it this app run) | `neutral` | Hollow/outline 8px dot (1px border in the neutral tone color, transparent fill) — the one new visual variant this phase adds to the dot system: an `outline` rendering of the existing `neutral` tone, not a new tone. Implement as a CSS modifier class (e.g. `.status-dot--outline`) layered on the existing `status-dot--neutral`, so `StatusTone` itself stays a closed 4-value enum |

**Accent (10%) additionally reserved for, this phase:** the "Nova sessão" primary CTA button, the focused-session row's left border, the search-bar active-input focus ring, the starting-state pulsing dot. Still never used for large fills or body text — same discipline as Phase 1.

**Destructive reserved for:** the Delete-session icon button's hover/focus state (icon turns `--color-destructive`, background stays transparent until hover) and the confirm-delete dialog's primary button fill. Nothing else in this phase uses destructive.


- Drawer expanded width: **640px fixed**, not resizable this phase (resizing is explicitly descoped — a reasonable follow-up, not a Phase 2 requirement; documented here so the executor doesn't invent a resize handle).
- Expanding the drawer never shrinks the board below its existing 1024px comfortable minimum — the window itself must be wide enough to fit sidebar (240px) + board (≥1024px) + drawer (640px); below that combined width the app relies on the OS window's own horizontal scroll/resize, same posture as Phase 1's "board scrolls horizontally rather than compressing" rule.
- Collapsing the drawer (clicking the collapse `X`/`—` button in the terminal chrome, or pressing `Esc` while the terminal has focus and the search bar is closed) returns to the 48px rail. This does **not** kill the session — it runs the Pattern 3 "lose focus" algorithm (dispose xterm instance, keep PTY alive, buffer bytes in memory) exactly as if the user had switched to a different session, just with no session focused at all.
- Rail behavior when collapsed: the terminal icon shows a small accent-colored numeric badge (top-right corner of the icon, e.g. superscript "2") when one or more sessions have a live `PtySession`, so background activity stays visible even with the drawer collapsed. Clicking the rail re-expands to the **last-focused** session; if no session was ever focused yet (first launch, drawer never opened), the rail stays in the same disabled/tooltip state as Phase 1 until the user picks a row from the sidebar directly.

## Session Sidebar & Row Anatomy

Replaces `SidebarPlaceholder`. Same 240px fixed width, secondary surface, unchanged from Phase 1's shell — only the content changes.

**Header (inside the sidebar, top):**
1. "Sessões" (Heading 18px/600)
2. "Nova sessão" button below/beside it — full-width or icon+label, accent background, `Plus` icon + label (Body 14px/400, white text on accent, matching Phase 1's primary-CTA button treatment from `AppShell.tsx`). Disabled entirely (not shown) when the tool-missing state is active — see `## Tool-Missing State`.

**List body**, two groups (only rendered if non-empty — see `zero-one-many` row in `## UI Considerations`):
- **Ativas** — sessions with a live `PtySession` in the Rust backend this app run (includes both "starting" and "exited-this-run" states, since both are lifecycle states of a session the user explicitly created this run — an exited-this-run session stays in "Ativas" with the exited dot/suffix rather than moving to "Histórico", since "Histórico" specifically means "discovered from disk, never spawned this run").
- **Histórico** — sessions discovered via `~/.claude/projects/<encoded>/*.jsonl` (Pattern 4) that have no live `PtySession` backing them. Not click-to-resume this phase (SESS-04/`--resume` is Phase 4) — clicking a historical row shows the `session.row.historicalTooltip` copy (e.g., as a toast or inline disabled-state hint) instead of opening the drawer.

Both groups sorted by `lastModified` descending.

**Row anatomy** (left to right), 40px row height, 8px (sm) vertical padding, full-width click target for live rows:
1. Status dot (8px, per `## Color` mapping above)
2. Session label: `"Sessão " + id.slice(0, 8)` in JetBrains Mono at Label size (12px/600) — e.g. "Sessão a3f91c2d" — plus the exited suffix `session.row.exited` appended when applicable
3. Relative timestamp (`date-fns`, locale-aware per active i18n locale), Label style, muted (70% opacity) — e.g. "há 2 min" / "há 3 dias"
4. On row hover only: two 32×32 icon buttons appear right-aligned — `Archive` (neutral) then `Trash2` (turns destructive-red on its own hover) — see `## Session Lifecycle Affordances`

**Selected/focused row** (the session currently shown in the expanded drawer): 4px accent-colored left border + secondary-surface background one shade darker (`color-mix(in srgb, var(--color-secondary) 85%, var(--color-foreground))`), consistent with Phase 1's "accent border on hover, no shadow" card language, just persistent instead of hover-only.

## Terminal Search Bar

`TerminalSearchBar` — driven by `@xterm/addon-search`. Toggled via the chrome header's `Search` icon, or `Ctrl+F`/`Cmd+F` while the terminal surface has focus. `Esc` closes it and returns focus to the terminal.

**Anatomy** (36px height, spans the full width of the terminal pane, secondary surface, 8px (sm) horizontal padding, sits between the chrome header and the xterm surface — pushes the surface down, does not float/overlay):
1. Search input, left-aligned, placeholder `terminal.search.placeholder`, auto-focused when the bar opens
2. Match counter (Label style) immediately right of the input — `terminal.search.matchCount` (e.g. "3/12") or `terminal.search.noMatches` ("0/0")
3. `ChevronUp` button (32×32) — previous match
4. `ChevronDown` button (32×32) — next match
5. `X` button (32×32) — closes the bar

**Behavior:**
- `Enter` in the input → next match (same as clicking `ChevronDown`)
- `Shift+Enter` → previous match
- No matches: input's focus-ring/border switches to the warning color (`--color-warning`), counter shows "0/0" — no destructive red, this is a "nothing found" state, not an error
- Search is case-insensitive by default (no case-sensitivity toggle this phase — not a stated requirement, kept out of scope deliberately rather than left ambiguous)

## Tool-Missing State

`ToolMissingState` (PROJ-04) — replaces the **entire sidebar body** (below the "Sessões" heading; the "Nova sessão" button is not rendered at all in this state, per the Common Pitfall 6 guidance in `02-RESEARCH.md`: never let the user discover absence only after attempting to create a session). Reuses the visual language of Phase 1's generic `ErrorState` component (centered warning icon + heading + body, no board-blocking) rather than introducing a new visual pattern — but is scoped to the sidebar column (240px), not a full-page takeover, since the board (Phase 1's core value) keeps working with or without Claude CLI/gsd-core present.

Three copy variants depending on what's missing (all defined in `## Copywriting Contract` above):
1. Claude CLI absent (regardless of gsd-core) → `session.toolMissing.claude.*`
2. gsd-core absent, Claude CLI present → `session.toolMissing.gsdCore.*`
3. Both absent → `session.toolMissing.both.*`

The collapsed drawer rail's terminal icon stays in the same disabled/tooltip-only visual state as Phase 1 whenever the tool-missing state is active (consistent: no functional entry point to sessions exists anywhere in the shell while blocked).

**Checked at:** project open/reopen (gsd-core, per-project) and app boot / first sidebar mount (Claude CLI, global) — before any "Nova sessão" affordance is ever rendered, per Pattern 5 in `02-RESEARCH.md`.

## Session Lifecycle Affordances

Both actions kill the session's live process tree if one exists (per SESS-06's "encerramento de árvore de processos" — this is true for both, not just delete); they differ only in confirmation friction and the underlying framing, since neither one touches the `.jsonl` history file that Claude Code owns (Pitfall 5 in `02-RESEARCH.md` — never delete another tool's data without an explicit, separately-scoped destructive action, which is out of scope this phase).

| Action | Icon | Confirmation | Result |
|---|---|---|---|
| **Archive** | `Archive` (neutral, no destructive color at any state) | None — immediate on click. Row fades + collapses out of the list over 150ms | Kills the PTY tree if alive; removes the row from the visible/active list this app run. The underlying `.jsonl` is untouched |
| **Delete** | `Trash2` (turns `--color-destructive` on row-button hover/focus) | `ConfirmDialog` (new small generic modal, not the full `ArtifactModal` — max-width 400px, centered, dominant surface, backdrop dims at the same 60%-opacity treatment as Phase 1's artifact modal) — heading `session.confirmDelete.heading`, body `session.confirmDelete.body` (explicitly clarifies the Claude Code history is not deleted, to set correct user expectations), primary button "Excluir" filled `--color-destructive`, secondary button "Cancelar" neutral outline | Same kill-tree + remove-from-list behavior as Archive, after confirmation |

**App-close behavior:** closing the app window while sessions are live does **not** show any confirmation dialog — `RunEvent::ExitRequested` (per `02-RESEARCH.md` Pattern 2) silently iterates and kills every live session's process tree before the app is allowed to exit. This is a deliberate, covered decision (not left unresolved): the alternative (a "sessions are still running, quit anyway?" dialog) would be inconsistent with the archive/delete actions above, which already treat killing the PTY tree as a low-friction, expected operation.
