# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This is the DELTA on top of `.planning/phases/01-espelho-fiel/01-UI-SPEC.md` and `.planning/phases/02-sess-o-viva/02-UI-SPEC.md`. Both prior contracts (spacing scale, typography scale, color tokens, desktop-only scope note, i18n-keys-from-day-one rule, xterm theme, `statusDotVariants`/`StatusTone` 4-tone system) are the standing contract and are **reused verbatim**, not redefined. This document only specifies what Phase 3 adds: contextual per-status action buttons on `PhaseCard`/`DetailPanel` (ACT-01), the `/gsd-*` injection contract and its busy/awaiting/no-session guard matrix (ACT-02/ACT-03), the terminal activity indicator (ACT-03 visual), and the GSD command toolbar + Cmd/Ctrl+K palette in the drawer aside (ACT-04).

**Mode note:** `03-CONTEXT.md` exists (smart discuss, `--auto`, recommended answers auto-accepted) and is treated as the standing locked decision set — its `## Implementation Decisions` are NOT re-litigated here, only translated into pixel/copy/state contract. Genuine gaps CONTEXT left open (`## Claude's Discretion`: exact busy/awaiting regex markers, specific `lucide-react` icons + palette ordering, i18n namespace naming) are resolved below with documented defaults and logged in `## UI Considerations` as `backstop`/`unresolved` where real ambiguity remains, per autonomous-mode instructions — no user was interrupted with questions.

## Typography

Unchanged — reuse the Phase 1 4-role scale verbatim (Label 12px/600, Body 14px/400, Heading 18px/600, Display 24px/600). See `01-UI-SPEC.md` `## Typography`.

**New usage mapping this phase:**

- **Label** (12px/600): card action button text, activity indicator text ("Ocupado"/"Ocioso"/"Aguardando permissão"), command palette's monospace `/gsd-*` token (muted, right-aligned per row), toolbar keyboard-shortcut hint badge ("Ctrl+K"/"⌘K"), guard tooltips (native `title` attribute, no explicit font control needed but conceptually Label-weight copy)
- **Body** (14px/400): detail panel action button text, command palette row label text, command palette empty-state body, transient "comando preenchido" hint
- **Heading** (18px/600): not introduced by any new Phase 3 surface (no new page/panel heading — the palette has no heading row, just a search input, to stay lightweight)
- **Monospace (JetBrains Mono Variable)**: command palette's `/gsd-*` command token, exactly as Phase 1 already uses monospace for artifact filenames and Phase 2 for session id labels — same font-family token, no new one

## Color

Unchanged tokens — reuse the Phase 1 palette + Phase 2's `StatusTone`/`statusDotVariants` system verbatim (`neutral`/`accent`/`warning`/`success`, plus the `--outline` CSS modifier). **No new `StatusTone` value is introduced this phase** — the terminal activity indicator reuses the existing 4-tone enum exactly, closing CONTEXT's loose "azul/atenção" wording (there is no blue token in the palette; `accent` — indigo — is the closest existing tone and is reused, consistent with `accent` already meaning "needs your attention" elsewhere, e.g. the starting-session pulse dot).

**Activity indicator tone mapping (ACT-03 visual):**

| Terminal activity state | Tone | Visual |
|---|---|---|
| Ocioso (idle) | `success` (green) | Filled 8px dot, static — identical rendering to the existing "live" session dot |
| Ocupado (busy) | `warning` (amber) | Filled 8px dot **with pulse** (new `.status-dot--pulse` CSS modifier, see below) |
| Aguardando permissão (awaiting) | `accent` (indigo) | Filled 8px dot **with pulse** (same modifier, different tone) |

**New CSS modifier — `.status-dot--pulse`:** `opacity` 100%→40%→100%, 1200ms loop, `ease-in-out` — one shared animation class layered on top of the existing `status-dot--warning`/`status-dot--accent` tone classes (same compositional pattern as the existing `status-dot--outline` modifier in `theme.css:87-95`), so `StatusTone` stays a closed 4-value enum and no new dot component is created. This is the first concrete implementation of the pulse animation Phase 2's `02-UI-SPEC.md` `## Color` table described in prose for the "starting" session state but never actually shipped in `theme.css` — Phase 3 introduces the real CSS class; retrofitting it onto the `starting` session-lifecycle dot is optional polish, not required this phase.

**Supersedes note (deliberate, documented override of Phase 2):** Phase 2's `## Color` table declared the "live" session dot as always `success`, static, regardless of focus. Phase 3 makes this **dynamic for sessions with a known activity state**: a live session's dot now reflects `idle`/`busy`/`awaiting` per the table above instead of being permanently `success`. Sessions with no activity signal yet (byte stream not yet observed this run) fall back to the Phase 2 static `success` treatment. `starting`/`exited`/`historical` dot variants are unaffected — activity state only applies to `live` sessions.

**Accent (10%) additionally reserved for, this phase:** card/detail-panel action button fill (idle state), the awaiting-permission activity dot, the command palette's selected/hovered row left-border, the toolbar's trailing "Comandos" button icon. Still never a large fill or body text color — same discipline as Phase 1/2.

**No new destructive-color usage this phase** — all Phase 3 actions are non-destructive (command injection, never a delete/archive). Phase 2's Delete-session confirm remains the sole destructive-token consumer.

## Injection Behavior Matrix (ACT-02 / ACT-03)

The single most load-bearing table in this document — resolves how EVERY command-emitting surface (card button, detail panel button, toolbar icon, palette row) behaves across every terminal/session state. All four surfaces obey this same matrix; no surface has bespoke behavior.

| Terminal / session state | Card or DetailPanel action (phase number `N` known) | Toolbar / palette — parameterless (`quick`, `next`, `progress`, `status`, `help`) | Toolbar / palette — parameterized, no bound phase (`discuss`, `plan`, `execute`, `verify`) |
|---|---|---|---|
| No active/live session, or Claude CLI/gsd-core missing | Disabled, `board.actions.guard.noSession` tooltip | Same — entire toolbar/palette renders in a disabled state with the same guard tooltip in place of the search input | Same |
| Ocioso (idle) | `writeSession(id, "/gsd-command-phase N\r")` — sends immediately | `writeSession(id, "/gsd-command\r")` — sends immediately | `writeSession(id, "/gsd-command ")` — **prefills only**, trailing space, no `\r`, cursor left in the terminal ready for the user to type `N` and press Enter themselves. Shows `board.actions.guard.prefilled` transient hint (2500ms timeout, same pattern as `SessionRow`'s historical-row hint) |
| Ocupado (busy) | Disabled, `board.actions.guard.busy` tooltip, **zero injection attempted** (never queued for later — CONTEXT explicit: block, don't queue) | Same | Same |
| Aguardando permissão (awaiting) | `writeSession(id, "/gsd-command-phase N")` — **prefills only**, no `\r` (never steals the Enter key from the CLI's own permission prompt). Shows `board.actions.guard.prefilled` hint | `writeSession(id, "/gsd-command")` — prefills only, no `\r`. Shows the same hint | `writeSession(id, "/gsd-command ")` — prefills only, no `\r`. Shows the same hint |

Both prefill paths (awaiting-permission reason, and parameterized-no-N reason) close the palette (if open) and move terminal focus to the xterm surface after writing, so the user can immediately type/press Enter without an extra click.

- No match: `commands.palette.empty`, Body style, centered, no icon, replaces the list area (search input stays visible/editable)
