<objective>
Build the terminal-state detection engine (ACT-03): classify the live PTY byte stream into `idle`/`busy`/`awaiting-permission` for EVERY live session (foreground and background), without reading `.jsonl` files (walled off by T-02-06) and without reintroducing per-byte re-renders. This is the most load-bearing architectural piece of the phase — it must use a second, always-on byte consumer in `channel.ts` (NOT the single focus-routed `bytesHandlers` slot), and a pure, unit-testable classifier so marker tuning never touches wiring.

Purpose: the busy guard that ACT-02/ACT-04 injection surfaces depend on, and the activity dot the sidebar/detail-panel/toolbar show, both read from the store field this plan populates.
Output: `src/pty/activity.ts` (pure classifier), the `activityHandlers` dual-map in `channel.ts`, the `activity` field + transition-gated `setActivity` in `session-store.ts`, and `useTerminalActivity` wiring, mounted in `TerminalView`.
</objective>

## Phase Goal (user story)

**As a** GSD developer with several live Claude sessions, **I want to** see at a glance whether each session is idle, busy, or awaiting permission, **so that** the board never injects a command into a session that is mid-task.
