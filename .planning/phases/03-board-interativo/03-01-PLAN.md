</objective>

## Phase Goal (user story)

**As a** GSD developer working a project on the board, **I want to** trigger the correct `/gsd-*` command for a phase's status directly from its card, **so that** I can drive the GSD flow from the board without retyping commands.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| disk (`.planning/` phase-directory names) → renderer state | `phase.id` is derived from directory names that may originate from a cloned/shared repo — untrusted input |
| renderer → Rust PTY (`write_session`) | the injected command string crosses into a live shell/CLI behind the PTY |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Tampering | `sanitizePhaseId` / `PhaseCardAction` injection string | high | mitigate | Validate `phase.id` against anchored `^\d{2,}(\.\d+)?$` before interpolation; a non-match yields a null action (no button), never a best-effort-sanitized string written to the PTY |
| T-03-02 | Denial of Service (soft, UX) | `writeSession` call in the action handler | low | mitigate | `.catch()` every `writeSession`; surface `board.actions.error.injectFailed` and re-enable — no silent drop of a user action |
</threat_model>
