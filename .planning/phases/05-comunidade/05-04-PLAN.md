<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| remote update endpoint → installed app | A compromised/MITM'd endpoint could serve a malicious installer; only the ed25519 signature (keyed to a private key never uploaded) gates install |
| GitHub Actions secrets → release artifacts/logs | Signing secrets must reach tauri-action without leaking into logs or artifacts |
| third-party GitHub Action → release pipeline | tauri-action executes inside CI as a supply-chain input |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-07 | Tampering / Elevation of Privilege | `plugins.updater` (auto-update = RCE vector) | critical | mitigate | The updater installs only artifacts whose ed25519 signature verifies against the configured `pubkey`; the shipped config MUST carry the maintainer's REAL pubkey (a placeholder must never ship) and an HTTPS `endpoints` URL, and the insecure-transport override flag must stay absent. This session scaffolds a base64-shaped PLACEHOLDER + HTTPS endpoint and makes pubkey-presence/HTTPS/no-insecure-flag checkable acceptance criteria; the real key is a blocking maintainer handoff (Task 3), never generated here |
| T-05-06 | Information Disclosure | `release.yml` signing secrets | high | mitigate | `TAURI_SIGNING_PRIVATE_KEY` / `_PASSWORD` referenced only via the Actions secrets context inside `env:` passed straight to tauri-action; never in `run:` echo/transform steps (GitHub does not redact re-encoded copies); no key literal committed to repo/docs |
| T-05-SC | Tampering (supply chain) | `tauri-apps/tauri-action@v1` | medium | mitigate | Pinned to the official `@v1` major tag (not `@main`/`@latest`); maintained by the same tauri-apps org already trusted across the dependency tree — no new untrusted third party |
</threat_model>
